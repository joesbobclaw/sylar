# Ability specification template

## Status

Proposed | Spike | Experimental | Production candidate | Acquired

## Source behavior

First-party source and concrete observable behavior.

## Gap classification

True gap or partial/productized gap. Name the nearest OpenClaw equivalent.

## Outcome

What becomes possible for a user.

## Non-goals

What this work explicitly does not attempt.

## User stories

Concrete scenarios with actors, resources, and completion criteria.

## Proposed design

Components, data contracts, lifecycle, persistence, and UI.

## Trust and safety

Authority, identity, secrets, prompt injection, data boundaries, approval, idempotency, recovery, and audit.

## MVP

Smallest useful implementation.

## Acceptance tests

Falsifiable tests, including adversarial and recovery cases.

## Rollout

Shadow, opt-in, default, and rollback stages.

## Open questions

Decisions that require evidence rather than assumption.

## Acquisition test

One sentence defining when the capability is genuinely acquired.
